# 为什么不用高饱和色

> 一份实测故事 + 安全色七原则的推导过程。

## 起因

最初做公众号排版时，我们用了 Tailwind 风格的高饱和色：`#2563eb` 蓝、`#d97706` 琥珀、`#059669` 薄荷。在浏览器里预览很漂亮——鲜艳、现代、有冲击力。

然后粘贴到公众号编辑器，开深色模式预览。

**灾难。**

- 蓝色块变成了一种说不清的灰紫，像脏衣服
- 琥珀色块在深底上几乎看不见字
- 薄荷绿和深色背景合成后，像是 90 年代的 Windows 主题色

我们试过「绕过」深色模式：白底画布 + `color-scheme: light`。**无效。** 公众号的深色 remap 是强制的，不走 `color-scheme`。

## 实测过程

于是开始系统测试。搭了一个测试页（模块 A–K），把每个色族按 50→500 明度阶梯铺开，在公众号编辑器里**浅色 + 深色各粘贴一次**，记录哪些组合不脏、哪些会脏。

### 发现 1：饱和度是元凶

同样明度的两个色：

- 高饱和 `#2563eb`（蓝 600）→ 深色模式脏
- 低饱和 `#B8C4CC`（莫兰迪蓝 200）→ 深色模式干净

差别在饱和度，不在色相。公众号深色 remap 对高饱和色做「明度反转」时，会把它推到一个不自然的色相区间。低饱和色反转后仍落在「灰」的区间，视觉上可接受。

### 发现 2：中明度最稳

太浅（50 阶）在浅色模式下没存在感；太深（500 阶）在深色模式下和背景糊在一起。**100–300 阶**作大面积底最稳，400 阶做边框，500 阶只做深壳点缀。

### 发现 3：字色不能跟着底色走

最初想「蓝色底配蓝色字」，深色模式下蓝字在蓝底上直接消失。

改成：**浅底统一 `#383838` 正文，深底统一 `#F4ECD7` 正文**。字色和底色脱钩，用中性色阶（N/W 方案），只用底色表达色彩倾向。标签等小面积点缀可以用同族色，但正文不行。

### 发现 4：边框要同族加深

最初用对比色描边（蓝底配橙边），深色模式下边框和底色一起被 remap，对比关系全乱。

改成：**边框 = 底色同族加深一档**（scale.400）。深色模式下边框和底色一起变深，层次关系保持。

## 安全色七原则

实测归纳出 P1–P7，详见 [methodology.md](methodology.md) §4。核心三条：

1. **低饱和、中明度**——避免高饱和色作大面积底
2. **字色和底色脱钩**——浅底 N、深底 W，不用彩色字当正文
3. **不绕过 remap**——靠色板适配，不靠 `color-scheme` hack

## 高亮色 H1/H2 的引入

安全色解决了「大面积底」的问题，但「阶段 tag、左竖线、`<strong>` 点缀」这种小面积高亮，安全色太灰，没强调感。

最初用 `#64d2ff`（Apple 系统蓝），但它是高饱和色，违背 P1。v0.5 引入两个**专门用于小面积**的高亮色：

| ID | 名称 | base | 用法 |
|----|------|------|------|
| H1 | 暖琥珀 | `#B8A078` | 暖主题：时间轴 tag、左 border-left、浅底 strong |
| H2 | 板岩青 | `#8AADA4` | 冷主题：架构 accent 线、替代 `#64d2ff` |

**关键约束：** 高亮色**禁止**作大面积底。它们只用于 tag / 3px 以内竖线 / span 级 strong。`sage.base` 仍可作 T03 色块底，但那是「色族底」不是「高亮」。

## 验证方法

每个色族/组合都要过这一关：

1. 浅色模式粘贴到公众号编辑器，截图
2. 切深色模式，截图
3. 对比：底色是否发脏、字色是否可读、边框层次是否保持
4. 通过的写入 `wechat-safe-palette.json`，标 `status: validated`

测试编号体系见 `wechat-safe-colors/palette-reference.md`。新贡献色族需附同等验证截图。

## 给贡献者的建议

1. **别引入高饱和色作底**——哪怕它在浏览器里很好看
2. **新色族先做 50→500 阶梯**——单阶不够用
3. **字色方案选 N/W/B/C 之一**——别自创第五套
4. **边框用同族 400**——别用对比色
5. **深底卡全篇 ≤2 张**——多了压迫感强
6. **每条新规则附实测截图**——「我觉得这样好」不算验证
