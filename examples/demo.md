# 写 Markdown 的，不该自己排版

内容和排版，我把它拆开了。

---

天下苦公众号排版久矣。

作为一个懂点设计的公众号创作者，你一定遇到过这样的苦恼：正文在 Cursor 里用 Markdown 写得行云流水，三千字加上 AI 辅助，实际也就十分钟搞定。然后——**排版花了两个多小时**。

调字号，调行距，某一段想居中做成金句，复制到公众号编辑器一看，样式全乱了。再改，再粘贴，再乱。循环了大概六七次，我盯着屏幕发呆：

> 「我到底是来写内容的，还是来当排版工的？」

那一刻我决定做一件有点「不自量力」的事——**做一个公众号排版工具**。

## 问题出在哪

写完一篇文章，打开某个「Markdown 转公众号」工具，粘贴，预览——**能用，但也就那样**。字号统一、段落整齐，仅此而已。想要某一段右对齐？不支持。想要金句居中放大？自己写 HTML。想要对比卡片、时间线？抱歉，模板里没有。

问题的根源，不是「模板不够多」，而是**我们把内容和排版绑死在了同一条链路上**。

## 内容和排版，本来就不该是一回事

做建筑的时候，我学到一个概念：**方案设计**和**施工图**是两套图纸。方案解决「空间好不好用、好不好看」；施工图解决「梁要多厚、管怎么走」。你不能在方案阶段就把每根钢筋的位置定死，也不能在施工图里重新讨论功能布局——**分层，才能各自迭代**。

写公众号，也应该这样：

| 层级 | 管什么 | 用什么 |
|------|--------|--------|
| **内容层** | 写什么、结构怎样 | Markdown |
| **排版层** | 怎么排、哪里用卡片 | LayoutDoc（AI + Skill） |
| **渲染层** | 长什么样 | Design Token 主题 |
| **导出层** | 能不能粘贴进微信 | 内联 HTML + 兼容清洗 |

**Markdown 只管内容。** 排版是另一套决策，由独立的「排版文档」来描述。

> **内容 ≠ 排版。写稿的归写稿，排版的归排版。**

## 写在最后

这套方法还在打磨，但方向我想是清楚的：**让创作者回到内容本身，把排版交给懂微信的 AI**。

如果你也苦排版久矣，欢迎一起来折腾。
